# Отчёт по ТЗ № 4Б

## Реализовано в тестовой среде

- Нормализованный слой Firestore для классов, учеников, финансового журнала,
  магазина, заявок, покупок, достижений, сезонов и безопасного рейтинга.
- Атомарные начисления/списания с независимыми `balance` и
  `lifetimeEarned`, проверкой отрицательных значений и ключом идемпотентности.
- Массовые операции выполняются по ученику и возвращают отдельный результат
  каждой операции, поэтому ошибка одного ученика не отменяет успешные.
- Ученик создаёт только собственную заявку. Цена и лимит повторно проверяются
  во время подтверждения, а списание, покупка, статус и достижения записываются
  одной транзакцией.
- Ручное достижение и его бонус выдаются одной транзакцией и не повторяются.
- Новый сезон архивирует итоговые показатели и обнуляет текущие `balance`,
  `lifetimeEarned` и счётчики покупок. История и достижения сохраняются.
- Старый `/trackerApps/main` запрещён в защищённом контуре.

## Автоматические достижения

| ID | Название | Точное условие | Финкоины |
|---|---|---|---:|
| `first_coin` | Первый финкоин | `lifetimeEarned >= 1` | 0 |
| `balance_50` | Копилка | `lifetimeEarned >= 50` | 0 |
| `balance_100` | Состоятельный пират | `lifetimeEarned >= 100` | 0 |
| `balance_300` | Адмиральские амбиции | `lifetimeEarned >= 300` | 0 |
| `first_purchase` | Первая покупка | не менее 1 подтверждённой покупки | 0 |
| `five_purchases` | Шоппинг | не менее 5 подтверждённых покупок | 0 |

Покупочные достижения проверяются только при подтверждённой покупке. Факты
выдачи имеют детерминированные ID; повторное начисление отсутствует.

## Миграция

`scripts/migrate-emulator-data.js` принимает искусственный JSON через
`--input=<путь>` или использует встроенный пример. Скрипт:

- отказывается запускаться без локального `FIRESTORE_EMULATOR_HOST`;
- принимает только project ID с префиксом `demo-`;
- сохраняет ID классов, учеников, операций, товаров, заявок и достижений;
- объединяет дубли ручной выдачи из трёх старых мест хранения;
- не восстанавливает покупку без подтверждающей финансовой операции, а
  помещает такой случай в `discrepancies`;
- сообщает отдельно, когда `lifetimeEarned` пришлось вывести из истории.

## Неоднозначность сезонов

Утверждённые накопительные условия сформулированы «за курс», поэтому новый
сезон начинает `lifetimeEarned` с нуля. Уже выданные достижения сохраняются и
не выдаются повторно. Если в будущем сезон и курс станут разными понятиями,
потребуется отдельное решение владельца продукта; текущее поведение не менялось.
