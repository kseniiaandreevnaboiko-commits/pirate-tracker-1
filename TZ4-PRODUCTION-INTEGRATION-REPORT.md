# Отчёт: интеграция защищённой версии в существующий «ФинЗОЖ»

Дата: 15 октября 2026 года. Ветка: `feature/tz4b-secure-economy`.

## Результат

Подготовлен release-кандидат для прежнего GitHub Pages и существующего Firebase-проекта `tracker-progress-2b682`. Новый сайт, новый Firebase-проект и отдельная база не создавались.

Production Firebase, `/trackerApps/main`, опубликованные Rules и GitHub Pages не изменялись. Git push и deploy не выполнялись.

## Реализовано

- Защищённая авторизация включена как основной режим текущего приложения, а не как отдельная тестовая страница.
- На GitHub Pages клиент выбирает существующий проект `tracker-progress-2b682`.
- Эмуляторы можно выбрать только явно через `?emulator=1` на localhost/127.0.0.1.
- В production не вызываются `connectAuthEmulator` и `connectFirestoreEmulator`.
- Кабинеты проверяют защищённую Firebase-сессию вместо старой PIN-сессии.
- Legacy-синхронизация общего документа `firebase-sync.js` не загружается в защищённом режиме.
- Ссылка приглашения сохраняет текущие `origin` и `pathname`, поэтому остаётся на прежнем GitHub Pages.
- Production-тексты восстановления пароля и панели доступа больше не называют среду эмулятором.
- Добавлены read-only backup, локальный dry-run, защищённое применение и read-only verify.
- Backup и migration plan имеют SHA-256; изменение файлов обнаруживается.
- Apply создаёт только отсутствующие документы, пропускает полностью совпадающие и останавливается при любом конфликте.
- Apply не удаляет и не изменяет `/trackerApps/main`.
- Production-запись требует одновременно `--execute`, два совпадающих project ID, SHA-256 источника и точную переменную подтверждения.
- `backups/` и `migration-plans/` исключены из Git.
- Подготовлен согласованный production-план и аварийный откат.

## Что осталось до статуса «можно обновлять»

1. Вручную пройти визуальный чек-лист из `TZ4V-STAGE1-REPORT.md`: встроенный браузер в среде проверки недоступен.
2. Подтвердить фактический домен GitHub Pages в Firebase Authentication Authorized domains.
3. Подтвердить UID существующего учителя и `active: true` в `/authorizedTeachers/{uid}`.
4. С отдельного разрешения сделать read-only production backup и dry-run реальных данных.
5. Разобрать все реальные `discrepancies`, если они появятся.
6. Назначить окно обслуживания и только затем отдельно подтвердить migration apply, Rules deploy и Pages deploy.

До выполнения этих пунктов проект является подготовленным release-кандидатом, но не должен публиковаться.
