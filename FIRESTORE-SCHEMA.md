# Схема защищённых данных (ТЗ № 4Б)

Все рабочие сущности класса находятся под `/classes/{classId}`. Общий документ
`/trackerApps/main` в защищённом режиме не читается и запрещён правилами.

| Путь | Назначение | Кто читает | Кто изменяет |
|---|---|---|---|
| `/authorizedTeachers/{uid}` | серверная роль учителя | владелец UID | только администратор Firebase, не клиент |
| `/classes/{classId}` | параметры класса и активный сезон | учитель класса, привязанный ученик | учитель класса |
| `/classes/{classId}/students/{studentId}` | приватный профиль, `balance`, `lifetimeEarned` | учитель и сам ученик | учитель; ученик только однократно привязывает UID через приглашение |
| `transactions/{operationId}` | неизменяемый финансовый журнал | учитель и владелец профиля | только учитель, только создание |
| `rewards/{rewardId}` | каталог магазина | учитель; ученику только активные позиции | учитель |
| `purchaseRequests/{requestId}` | заявки | учитель и автор заявки | ученик создаёт `pending`, учитель меняет статус |
| `purchases/{requestId}` | подтверждённые покупки | учитель и покупатель | только учитель, только создание |
| `achievementDefinitions/{id}` | ручные достижения | учитель; ученику только активные | учитель |
| `automaticAchievementDefinitions/{id}` | утверждённые 6 автодостижений | учитель и участники класса | учитель; награда всегда 0 |
| `studentAchievements/{type_student_id}` | факты выдачи | учитель и конкретный ученик | только учитель, только создание |
| `seasons/{seasonId}` | активный сезон и архив итогов | учитель | учитель |
| `leaderboard/{studentId}` | безопасная публичная проекция | участники класса | учитель |
| `/studentInvites/{token}` | одноразовое приглашение | учитель; предъявивший токен | учитель создаёт, анонимный UID атомарно погашает |
| `/studentBindings/{uid}` | связь Auth UID с профилем | сам ученик и учитель класса | атомарное погашение приглашения; учитель может отозвать |

Финансовые операции используют идентификатор операции как ID документа.
Повторная запись не меняет баланс. Подтверждение покупки использует ID заявки
для документов покупки и списания. Выдача достижения использует составной ID
из типа, ученика и достижения, поэтому повторная выдача не создаёт бонус.

`leaderboard` не содержит баланс, UID владельца, операции, покупки,
достижения или иные приватные поля.
